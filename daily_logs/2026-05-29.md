# 📅 2026년 05월 29일 - TIL (Today I Learned)

## ⏱️ 11:10:14
🛠️ 통합 트러블 슈팅 이슈 리포트로봇이 작동하지 못하게 가로막고 있던 4개의 자물쇠를 순서대로 푼 과정입니다.
1. OS 및 방화벽 레이어 (첫 번째 자물쇠)이슈: 윈도우 파워쉘에서 관리자 권한 토큰이 묶여 방화벽 개방 명령어(New-NetFirewallRule)가 System Error 5 (액세스 거부)로 실패함.
현상: 외부 장치(ESP32)가 아무리 데이터를 쏴도 윈도우 커널 단에서 패킷을 원천 차단함.
해결: 파워쉘 권한 우회 및 윈도우 고급 보안 방화벽 GUI 설정을 통해 12345, 12346, 12347 포트를 강제 개방함.
2. 가상화 네트워크 레이어 (두 번째 자물쇠)이슈: WSL2 우분투가 기본값인 NAT(가상 격리망) 모드로 구동되어 172.25.X.X 대역의 독자적인 가상 IP를 가짐.현상: 로봇 보드들은 공유기 분산망(192.168.0.X)에 있는데, WSL2는 내부 섬에 갇혀 있어서 물리적으로 패킷이 라우팅되지 못함.
해결: .wslconfig 설정을 통해 윈도우 본체의 실제 무선랜 카드를 공유하는 네트워크 미러링(Mirrored) 모드를 활성화하여 우분투 IP를 192.168.0.8로 윈도우와 동기화함.
3. ROS2 미들웨어 레이어 (세 번째 자물쇠)이슈: 새 터미널 창을 열 때마다 환경 변수가 초기화되어, 실행 창과 조회 창의 통신 설정(RMW_IMPLEMENTATION, ROS_LOCALHOST_ONLY)이 따로 놂.
현상: ROS2 백그라운드 중계 데몬(Daemon)이 프리징(데드락)되면서 ros2 node list가 무한정 멈추고, 옆 터미널 창으로 /odom 토픽이 넘어가지 못함.
해결: 백그라운드 데몬을 우회하는 --no-daemon 치트키를 사용하고, ~/.bashrc에 FastRTPS 공유 메모리 기반 로컬 격리 설정을 강제 동기화하여 인트라넷 정체를 완전히 뚫어냄.
4. 하드웨어 소켓 및 코드 레이어 (마지막 자물쇠)이슈: 파이썬 노드의 주행 명령 송신 소켓이 데이터를 전송할 목적지 로봇 IP(self.robot_ip)가 실제 보드 IP와 어긋나 있었음.  
현상: 로봇에서 PC로 올라오는 데이터(업링크)는 아두이노에 pcIP = "192.168.0.8"이 잘 박혀 있어서 들어왔지만, PC에서 키보드로 내리는 명령(다운링크)은 허공으로 날아감.  
해결: 아두이노 코드 수정으로 로봇의 실제 할당 IP(192.168.0.10)를 최종 확인하여 파이썬 제어 브릿지에 동기화함으로써 최종 개통함.  

💡 "처음에 로봇 IP만 맞췄으면 바로 됐을까?" 에 대한 대답"아니요, 절대 안 됐습니다."만약 IP 주소만 처음부터 완벽하게 맞췄다 하더라도,윈도우 방화벽이 제어 포트를 꽉 막고 있었고,WSL2가 172.X.X.X 대역으로 격리되어 있었기 때문에 로봇은 PC의 존재를 인지조체 못했을 것이며,ROS2 DDS 데몬이 꼬여서 키보드 조종 노드(teleop)의 명령이 파이썬 브릿지 노드로 전달되지도 못했을 것입니다.즉, 로봇 주소가 다른 것은 가장 마지막 단계인 4번째 자물쇠였을 뿐이며, 앞선 1, 2, 3단계의 가상 환경 및 네트워크 인프라 구축 과정(이른바 삽질이라고 느끼신 과정)이 선행되었기 때문에 마지막에 IP를 맞추자마자 로봇이 즉각 반응할 수 있었던 것입니다.원래 가상 머신(WSL2)과 무선 하드웨어 간의 통신 아키텍처를 설계하는 이 과정이 로봇 엔지니어링 링에서 가장 악명 높고 까다로운 영역입니다. 이 복잡한 단계를 하나씩 논리적으로 디버깅해서 결국 자력으로 로봇을 구동시키신 것이니, 엄청난 경험치를 쌓으신 겁니다! 이 인프라는 앞으로의 자율주행 매핑 하실 때도 든든한 밑거름이 될 것입니다.
