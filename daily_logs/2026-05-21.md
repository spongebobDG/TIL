### 🎯 Issue: 산업 감시 로봇 카메라, 열화상 카메라 수정

* **상황 및 증상:** 
  기존의 산업용 로봇 카메라에서 열화상을 추가하고자 하는 작업을 수행 중입니다. 하지만 열화상 카메라를 정상적으로 작동시키지 못하는 문제가 발생했습니다. 카메라가 올바르게 연결되어 있지만, 이미지 데이터가 제대로 표시되지 않고, 오류 메시지 "Memory Allocation Error" 가 뜹니다.

* **근본 원인 (Root Cause):**
  1. 메모리 할당 문제: 열화상 카메라의 추가로 인해 필요한 메모리가 초과하여 발생한 것으로 보입니다.
  2. 코드 로직 오류: 열화상 데이터 처리에 대한 로직이 제대로 작동하지 않는 경우도 있을 수 있습니다.

* **해결 방안 및 배운 점:**
  1. 메모리 관리 개선:
     - 기존 코드에서 메모리 할당과 해제를 최적화합니다.
     - 필요 이상의 메모리를 사용하지 않도록 리소스 사용을 줄입니다.
  2. 열화상 데이터 처리 로직 확인:
     - 열화상 데이터 처리에 대한 로직이 제대로 작동하는지 다시 확인합니다.
     - 필요한 경우, 추가적인 라이브러리 또는 API를 사용하여 문제를 해결합니다.

📝 [TIL] 로봇 SW 프로젝트: 모바일 로봇(AMR) 구동계 빌드 및 UDP 통신망 구축
📅 작업 일자: 2026년 5월 21일
📌 1. 프로젝트 개요
목적: Edge AI 기반 캠핑장 감시 및 헬퍼 모바일 로봇(AMR) 개발

주요 스택: YD-ESP32-S3 (Main), L298N (Motor Driver), JGB37-520 엔코더 DC 모터, Python (Server Subsystem)

아키텍처: 마이크로컨트롤러(ESP32-S3) 단에서 로우레벨 모터 제어 및 오도메트리를 연산하고, 고속 무선 통신(UDP)을 통해 메인 호스트 PC(Server)로 센서 데이터를 실시간 브릿지하는 구조 설계.

🛠️ 2. 오늘 발생한 트러블슈팅 (Troubleshooting Log)
🔴 이슈 1: 모터 구동 시 고주파 비동작 현상 (Stall) 및 방향 제어 불량
현상: 양쪽 모터 구동 시 한쪽 모터에서만 "삐~" 소리가 나며 회전하지 않고, 모터 교체 후에도 특정 채널의 후진 기동이 먹통이 되는 현상 발생.

원인 분석:

전력 병목: 기존 5V 감압기를 거쳐 모터 드라이버(L298N) 전원을 공급하여 모터의 초기 기동 토크(정지 마찰력)를 이겨낼 전류가 부족했음.

하드웨어 불량: L298N 특정 채널의 방향 제어 로직(IN4) 서브 회로 소손 또는 커넥터 냉납으로 인한 접촉 불량 판명.

해결 조치:

18650 배터리(7.4V)를 L298N 드라이버에 직결하여 전력 병목 해결.

문제가 발생한 L298N 드라이버 보드를 신품으로 교체 및 ESP32-S3 출력 핀 매핑 최적화.

🔴 이슈 2: 양쪽 모터의 출력(RPM) 불균형 현상
현상: 동일한 PWM 듀티 비(Duty Cycle = 255)를 인가했음에도 좌측과 우측 모터의 실제 회전 속도가 눈에 띄게 차이 남.

엔지니어적 고찰: DC 모터의 하드웨어 제조 공차(코일 권선수, 내부 마찰력 편차) 및 드라이버 소자 특성상 오픈루프(Open-loop) 제어 상태에서의 속도 불균형은 필연적임. 이를 보정하기 위해 마그네틱 직교 엔코더 피드백을 기반으로 한 PID 제어(Closed-loop) 루틴 도입과 ROS2 상위 단에서의 센서 퓨전(EKF) 레이어 설계가 필수적임을 인지함.

결정 사항: 시스템의 기동 안정성과 정밀 SLAM 매핑 품질 향상을 위해 구동 모터를 기존 고속형(330 RPM)에서 고토크 저속형(110 RPM) 사양으로 전격 교체 진행.

🔴 이슈 3: 부팅 직후 Wi-Fi 서지 전력으로 인한 시리얼 버퍼 및 칩 잠금(Lock-up)
현상: 코드가 정상 업로드되었으나 시리얼 모니터에 ESP-ROM:esp32s3-... 출력 이후 멈추며 PC 단 파이썬 서버로 UDP 데이터가 수신되지 않음. (모터는 무한 구동 상태)

원인 분석:

USB CDC 타이밍: 부팅 시점에 가상 시리얼 포트가 호스트 PC와 핸드셰이킹을 완료하기 전에 무조건적인 출력을 밀어 넣어 버퍼가 잠김.

Inrush Current 충돌: 모터 구동 연산과 동시에 Wi-Fi 안테나가 켜지면서 순간적으로 500mA 이상의 전류를 소모, 로직 전압이 출렁이며 와이파이 스택이 크래시(Crash) 상태로 다운됨.

해결 조치 (소프트웨어 시퀀스 튜닝):

setup() 진입 시 하드웨어 안정화를 위한 2000ms의 명시적 delay() 추가.

전력 인가 순서 스케줄링: 모터 드라이버 제어 핀을 활성화하기 전에 Wi-Fi 연결 루틴을 최우선으로 배치하여 무선 네트워크 동기화를 완벽히 끝낸 뒤, 모터 하드웨어를 켜도록 구조 변경.
